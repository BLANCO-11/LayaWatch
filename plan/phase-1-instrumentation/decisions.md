# Phase 1 decisions

Phase-local ids (`P1-Dn`); cross-phase decisions keep the `plan/README.md` numbering.

| ID | Title | Date | Status | Rationale | Alternatives | Consequences |
|---|---|---|---|---|---|---|
| P1-D1 | Sampled-out traces still reach the writer: `meta.sampled=False`, observations cleared, rollups updated, no ring or trace row | 2026-09-22 | accepted | docs/observability-model.md section 5 requires rollups to stay accurate while detail is skipped; the original pin ("on_trace only for kept") would have undercounted requests | deliver full spans then drop in the writer (wasted recorder work); store a marked trace row (api-reference summary has no `sampled` field, the list view would show broken empty traces) | metrics never drift under sampling; the writer branches on one meta flag; `obs_dropped_total` counts sampling drops (architecture section 9) |
| P1-D2 | Playground runs (`session_id` set or `meta.source=playground`) bypass sampling entirely | 2026-09-22 | accepted | observability-model section 5: "errors, refusals and playground runs are always recorded" | sampling applies uniformly (loses operator runs the console depends on) | force-keep implemented next to the error rule in `Context.finish`, tested at `sample_rate=0` |
| P1-D3 | Both adapters return the uniform api-reference section 4 shape; `RealAdapter` maps router-native payloads (`route_reason`/`lang` flattened), trace keeps both key names | 2026-09-22 | accepted | the handler must not know which adapter is wired; P0-D7 already pinned `route_reason` for predict and `reason` for route | return router-native from the real adapter (handler branches per adapter); change the fake (breaks Phase 0 tests and the documented fake contract) | adapter module docstring scopes both shapes; native-only keys (`repo`, `detection`, `workflow`) stay internal |
| P1-D4 | `EnglishOnlyError(ValueError, .detection)` is the typed 422 rejection; error codes pinned: `english_only`, `missing_or_invalid_credential`, `invalid_request`, `internal_error` | 2026-09-22 | accepted | only the engine layer runs `analyse()`; the legacy host's 422 body is reproduced including `details.detection`; subclassing ValueError keeps generic engine ValueErrors failing closed as 400 | string-matching exception messages (brittle); 422 in the HTTP layer (wrong layer, no detection payload) | middleware/handlers catch the typed error before the ValueError path; covered by unit tests and the live 422 trace |
| P1-D5 | Legacy API keys import verbatim (unpeppered SHA-256 digests kept as stored) and `verify_key` does a constant-time dual-format check (peppered HMAC or legacy SHA-256, no short-circuit); prefix normalized 12 -> 8 chars | 2026-09-22 | accepted | every plaintext that verified pre-import must verify post-import (the legacy file stores no peppered form, re-hashing is impossible); api-reference section 9 pins prefix = first 8 | reject legacy digests (breaks criterion 8's real migration); store both formats (nothing to convert) | import renames the file only after commit; second start logs `already imported; skipping`; one dual-format compare per authed request (Phase 7 can re-verify) |
| P1-D6 | Trace closes on the server's `on_sent` hook (`close_on_sent=True`): `response.send` spans the real socket write and the `finally` in `_send` guarantees closure even on broken pipe | 2026-09-22 | accepted | architecture section 4 orders `response.send` before trace close; measuring anything earlier would not include the write | close on dispatch return (undercounts response.send; clock stops before bytes leave) | hook exceptions are logged and never fatal; every produced response path reaches the hook |
| P1-D7 | Lazy engine: `find_spec("laya")` decides real vs fake adapter at boot; checkpoints load on first predict; healthz never touches the engine | 2026-09-22 | accepted | cold-start budget is "3 s plus model load" (performance.md); CI and engineless dev boxes keep working (`device=fake` in healthz, warning logged) | preload at boot (blows the cold-start budget, blocks healthz for ~26 s); config row for engine choice (no such row in section 6; not inventing config) | first predict pays `model.load` (recorded as a span); `laya` absent is a warning, not a crash |
| P1-D8 | Middleware auth uses a short-lived per-engine-request SQLite connection and updates `last_used`/`request_count` directly in that transaction | 2026-09-22 | accepted | handlers never write observability data (they enqueue); key bookkeeping is not observability and must be synchronous with verification | enqueue the touch (writer ordering makes `request_count` lag and adds queue load for a 2-row update); one shared connection (thread-affinity and lock contention for no gain) | engine-only cost: one connection open per /predict or /route (~microseconds under WAL); Phase 7 can pool if bench shows it |
| P1-D9 | Engine memory floor `GB_PER_CHECKPOINT = 1.5 GiB` checked against `/proc/meminfo` MemAvailable, fail-open when unreadable | 2026-09-22 | accepted | grounded in legacy measurements (~1.3 GB RSS per checkpoint) plus laya's ~1.5 GB fp32 weights per model plus headroom; deployment target is Linux | check at Total RAM (refuses loads the kernel could still satisfy); hard fail when /proc missing (breaks macOS dev) | `EngineMemoryError` message states needed vs available; test monkeypatches the reader on both sides of the floor |
| P1-D10 | `auth.armed` recorded as trace meta, not a span attribute (vocabulary frozen at `scheme`/`key_id`/`ok`); additive `Context.set_meta` merge helper added | 2026-09-22 | accepted | the vocabulary in observability-model section 2 is the contract; changing it ripples into Phase 2 readers | widen the vocabulary now (unreviewed doc change mid-phase); drop the information (ops wants to see auth mode on a trace) | `armed=false` is observable as `scheme=none` + `ok=true`; meta merge keeps producers from clobbering each other |
| P1-D11 | Retention/writer operational choices: rollup counters keyed by exact status with `percentiles=NULL`, latency/queue keyed `(model, route, status=0)`, parent percentiles merged as child-count-weighted approximations, 1000-row delete chunks committed per chunk, WAL checkpoint gated on `queue_idle` | 2026-09-22 | accepted | schema columns and observability-model sections 6-7 are the only sources; percentiles are documented as bucket-level; chunk commits release the write lock (performance.md intent) | exact parent percentiles (would require keeping raw samples for 90 days); larger chunks (longer lock holds); checkpoint unconditionally (fights the writer) | charts show bucket-level percentiles as the API promises; second retention pass is a no-op (tested); `apply()` returns per-action counts for evidence |
